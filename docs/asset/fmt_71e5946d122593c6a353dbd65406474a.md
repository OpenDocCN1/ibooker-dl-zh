
# 第八章：特性管理和实验

在第七章中，我们探讨了将软件部署到生产环境中的挑战和最佳实践。我们关注了减轻风险和确保可靠性的策略，包括渐进式部署策略，以及与强大的回滚机制相结合。这种方法有助于我们在新软件版本中早期发现问题，以保护生产系统的完整性。回想一下，我们提到了特性标志作为一项重要的渐进式部署策略；特性标志是一种在软件的单个版本中渐进式部署单个特性的机制。在本章中，我们将继续讨论特性标志作为管理特性部署工具的使用。

我们还将深入探讨特性标志的另一个作用——它们如何推动实验。虽然特性标志在降低部署风险和实现渐进式交付方面非常出色，但它们的影响远不止于此。当与人工智能结合时，它们使您能够运行实验来了解您的用户，优化您的特性设计想法，验证假设，并做出基于数据的决策，从而提高产品的可用性、参与度和整体业务成果。

特性管理和实验管理密切相关——特性标志是控制特定功能是否启用的基本开/关开关。特性管理系统提供了基础设施，用于控制在何种条件下以及何时将特性发布给哪些用户，而实验则利用这种控制来衡量每个变体的影响，并帮助团队做出数据驱动的决策。然而，尽管特性管理（带有特性标志）功能强大，但它们也伴随着自己的风险和挑战，我们也将探讨这些内容。

回想我们在第七章中关于 Knight Capital 事件的讨论。一次错误的软件部署在 45 分钟内导致了 4.6 亿美元的损失。事件发生在 Knight Capital 部署了其交易软件的新版本，该版本重新激活了一块休眠的遗留代码。一个配置错误的特性标志是罪魁祸首。这个标志本意是用来控制一块遗留代码是激活还是不激活，但错误地在一些服务器上启用，而在其他服务器上没有启用。这种不一致性触发了过时的逻辑，导致在不到一个小时的时间内发生了超过四百万笔错误交易。

尽管特性标志为团队以规模交付提供了巨大的潜力，但正如 Knight 事件所显示的，它们的误用或不当管理可能会引入重大风险。有效的特性管理需要周密的规划、彻底的测试和强有力的治理，以防止这类灾难的发生。

AI 正在通过使实验和实施变得更加容易和有洞察力来改变功能管理系统。现代 AI 驱动的平台可以以普通语言解释统计结果，根据用户模式提出最佳的推出策略，自动检测异常，甚至为特定实验生成定制化的实现代码。AI 增强减少了开发者的认知负担，同时使产品团队能够进行更复杂的实验。

在本章中，我们将检查缺乏 AI 能力的传统自建功能管理解决方案的局限性，并探讨现代 AI 增强系统不仅降低风险，而且释放功能管理和实验作为战略工具交付高质量软件的完整潜力。

# 现代软件开发中功能管理的益处

想象一下，我们的组织正在实施一个处理小型企业基本在线交易的支付平台。该平台支持支付处理、发票、基本分析和与电子商务平台的集成。我们持续且快速地发布新功能，以进行迭代改进并解决用户反馈。

在本节中，我们将探讨如何利用现代功能管理来使我们的组织摆脱传统发布流程的限制，从而加快我们的支付平台发布周期。我们将讨论如何使用功能管理来支持团队间的协作和渐进式交付。最后，我们将探讨功能标志如何帮助我们管理技术债务。

## 使用功能标志加速开发周期

在最简单的情况下，功能标志让我们能够部署“关闭”的新功能，将部署与功能发布解耦。然后，我们可以像开关一样翻转我们的功能标志，在以后激活功能，而无需部署新代码。这种方法帮助我们实现基于主干的开发。正如我们在第二章中看到的，持续集成涉及定期将代码更改合并到一个共享仓库中，自动测试确保每次集成的质量。基于主干的开发通过鼓励开发者直接向主分支（通常称为“主干”）进行小而频繁的提交来建立在此之上。

AI 驱动的系统通过从简单的提示中生成所需的代码来包装带有功能标志的代码块，从而加速了基于主干的开发过程。这减轻了可能对功能标志不熟悉的开发者的认知负担。使用功能标志包装所有新更改确保主分支保持稳定，即使在频繁的小提交中也是如此。

基于主干开发的其他替代方案包括长期存在的功能分支。使用这些替代方案，随着时间的推移，集成变得越来越困难，因为当多个团队在隔离的分支上工作一段时间后，他们通常只有在集成期间才会发现代价高昂的冲突。延迟集成也削弱了持续集成实践的好处，因为问题可能直到代码编写很久之后才被发现。主干开发被广泛认为是行业最佳实践，因为它有助于团队最小化合并冲突并保持对主分支的更新流稳定。合并变更的频率越高，主分支在任何时刻保持可部署的可能性就越高。这意味着更快、更可靠的发布。

在没有功能标志的情况下，部署主干开发所特有的小改动变得困难，因为所有更改都会立即在生产环境中生效。这需要团队之间紧密同步发布，限制了安全合并和部署不完整功能的能力。

功能标志为这一挑战提供了一个优雅的解决方案。通过允许开发者将新功能或实验性更改包装在功能标志中，他们可以在功能尚未完全开发或未经过生产测试的情况下将工作提交到主分支。标志有效地充当了守门人，确保在不准备好的情况下，不完整的功能在生产环境中保持关闭。这种方法消除了长期功能分支的需求。这有助于团队保持高部署速度，并验证代码库的其他方面，而不会受到功能完成时间表的限制。

## 解耦团队以减少协调开销

回到我们的支付平台，假设我们想要引入一个新的“订阅支付”功能。前端团队负责更新用户界面以支持周期性支付选项，后端团队必须实现管理订阅计划的 API，而分析团队的任务是跟踪订阅的用户行为。

没有功能标志，发布变成一个紧密耦合、高风险的事件。前端团队无法部署更新的用户界面，直到后端 API 上线，导致他们的工作在预发布环境中无法完成。后端团队无法全面测试 API，因为前端尚未集成，从而延迟了工作流程的验证。分析团队无法实施跟踪，因为订阅系统在生产环境中不可用。

这种依赖性迫使所有团队调整他们的时间表并协调一个庞大、单一且风险较高的发布。任何一个团队的延迟都会对其他团队产生连锁反应，造成瓶颈。如果发现一个关键错误，回滚功能意味着需要在所有团队中撤销工作，通常需要重新部署整个应用程序。

使用功能标志，每个团队都可以独立工作并逐步发布他们的更改。前端团队可以提前部署订阅管理用户界面，并通过功能标志隐藏它。这样做允许他们在等待后端准备就绪的同时，在生产环境中验证基本功能。后端团队可以实现并部署订阅 API 到生产环境，同样也通过功能标志进行控制。即使前端尚未上线，这些 API 也可以使用测试数据或有限用户进行测试。分析团队可以添加跟踪机制，并在另一个标志后面部署它们。他们可以通过模拟用户流程来确保正确收集指标，而无需将功能暴露给实际用户。

一旦所有组件都准备就绪，功能标志将开启以进行内部测试。一旦内部验证通过，该功能就可以推出到生产环境。我们不仅降低了发布“订阅支付”功能的发布风险，还降低了跨多个团队协调的开销。借助 AI 驱动的功能标志，这种协调变得更加流畅。AI 助手可以自动建议跨团队之间的标志依赖关系，当可能发生冲突时发出警报，并根据历史部署模式甚至推荐多团队功能发布的最佳顺序。

## 通过分阶段推出支持渐进式交付

当我们的“订阅支付”功能准备就绪时，我们可以使用功能标志逐步推出更新。使用现代功能标志系统，我们可以应用目标标准，如用户属性或百分比，以使功能对用户子集可用。这允许我们通过缓慢启用功能、监控其性能并在扩大到更广泛的受众之前进行调整，来在生产环境中进行验证。

在分阶段推出过程中，我们关注关键指标，如 API 错误率、响应时间、支付成功率以及客户反馈。如果我们观察到异常，例如失败的支付尝试激增、延迟增加或关于用户体验损坏的报告，这可能表明新功能引入了我们需要在继续之前进行调查的问题。

AI 通过预测定位和自适应控制显著增强了渐进式推出。机器学习模型分析用户行为模式，并预测最佳的推出策略——确定哪些用户应首先看到功能以产生最大影响。在推出过程中，AI 系统可以实时监控指标并根据性能数据自动调整速度，加速成功的部署，同时快速识别和遏制问题。

如果我们确实发现问题时，我们可以通过简单地关闭标志来轻松回滚。新功能对所有用户禁用，无需重新部署代码库。系统立即恢复到稳定、之前已测试的应用程序版本，最小化干扰，并为团队提供时间进行调查和解决问题。

## 使用功能标志管理技术债务

功能标志不仅用于启动新功能——它们在现代化遗留代码时可以作为安全网。这样，它们充当的是调光开关而不是简单的开/关按钮。在重构时，你可以逐步从旧代码过渡到新实现，同时保持出现问题时回滚的能力。

现代的人工智能原生功能管理系统擅长通过跟踪功能标志的使用模式并识别不再需要的标志来管理这种复杂性。机器学习算法可以分析代码依赖关系、标志状态和使用指标，以自动识别过时的标志并推荐其删除，从而防止技术债务的积累，同时保持系统完整性。

这通常是如何在实际中工作的：首先，你将新的、改进的代码实现与现有代码并排编写。然后，你创建一个功能标志，让你可以控制哪个版本运行——旧实现或新实现。这允许你在生产环境中使用一小部分流量测试新代码，而大多数用户继续使用经过验证的遗留代码。随着你对新实现越来越有信心，你可以逐步增加它处理的流量百分比。

这种方法对于大规模重构项目尤其有价值。你不必进行风险较高的“大爆炸”式替换，而可以使用功能标志以控制波次迁移用户。如果你发现任何问题，你可以立即将受影响用户切换回旧系统，而不会影响整个用户群。

这种模式的真正力量在于复杂系统，其中多个组件正在同时现代化。功能标志让你对现代化工作有精细的控制，让你能够在保持系统稳定性的同时协调多个重构倡议。

# 通过实验优化结果

我们已经看到功能标志如何帮助我们通过主干开发更快地发布，并消除协调多团队发布的需要。我们也看到了如何通过渐进式功能发布来降低发布风险。但是，如果我们发布的功能不提供价值，这又有什么意义呢？这正是 AI 驱动的实验介入的地方。

只有少数功能管理系统包括对实验的强大支持，使团队能够在其现有的应用程序基础设施中直接运行受控的、可衡量的测试。通过结合细粒度定位、用户群体的随机百分比分配和自动统计分析，这些系统允许工程和产品团队在用于功能发布的同一基础设施中无缝进行实验。这消除了对单独实验平台的需求，这意味着你只需要管理、监控和编写单个模式的集成代码。

设计良好的实验可以改变产品开发。而不是依赖于主观意见和无休止的辩论，你可以使用现实世界的用户行为来指导你的决策。这样做将会议室的推测和无休止的辩论替换为关于实际会吸引用户的变化和新功能的具体数据。功能标志使我们能够将用户分成组（例如，A 组和 B 组），并让每个组都接触到该功能的不同变体。例如，在一个在线支付平台上，一个组可能会看到“快速支付”按钮，而另一个组可能会体验到更新的“快速结账”工作流程。

通过使用功能标志，我们可以并行部署这些变体，实现提供实时、直接比较不同版本的对比实验。这种方法在测试变体时具有明显优势，因为在常规波动、季节性差异、营销活动的存在或其他因素可能导致结果偏差。通过并排实验，我们确保两个版本都受到相同条件的影响，以获得最可靠和最准确的观点。这些比较帮助我们自信地确定哪个版本能为用户提供最大价值，而不会受到顺序测试带来的噪音和不确定性。

现代人工智能极大地加速了我们的实验能力。例如，一种称为“多臂老虎机”的机器学习方法使用强化学习在实时动态地将更多流量分配给表现更好的变体。例如，如果早期数据显示“快速结账”优于“快速支付”，AI 会自动将更多用户路由到获胜的变体，同时实验仍在进行中，在测试进行中最大化商业价值（并最小化损失）。这种自适应优化确保用户能够更快地体验到最佳版本，而无需等待手动分析和决策。

## 构建结构良好的实验

有效的实验始于一个与你的业务目标一致且概述具体、可衡量目标的明确假设。例如，你可能假设“快速结账”工作流程将通过简化支付过程来提高转化率。重要的是要记住，实验的目的不仅仅是确认你的假设——它是为了学习。与你的假设相矛盾的结果并不是失败；这些实验提供了有价值的见解，可能会节省在不太可能实现目标的项目上的数月投资。

一个好的实验确保结果是有意义和可操作的。它将功能性能与外部因素分开，以便观察到的结果可以仅归因于正在测试的变化。随着实验在团队和产品之间的扩展，以下标准对实验的指导至关重要。

### 强大、清晰的指标

每个实验都应该从一个定义良好的假设和一个关键指标开始，该指标捕捉到成功的样子。例如，如果你正在测试“快速结账”工作流程，你的主要指标可能是从结账开始到完成之间的转化率。清晰的指标使实验聚焦，实现可衡量的进步，并防止事后合理化。同样重要的是要确定护栏指标——如错误率或客户流失率等次要指标，这些指标可以发出意外副作用的通知，并防止你为了单一个数的优化而牺牲整体健康。

### 目标化和随机化的受众

接下来，专注于有效地定位你的实验。能够针对特定用户群体定制实验——例如通过设备类型、位置或客户层级——是至关重要的。但即使在这些定制受众中，也必须保持随机化以避免结果中的偏差。例如，不要在没有随机抽样的情况下在同一地区与另一地区测试相同的功能。这确保了观察到的任何差异都是由于功能本身，而不是外部因素。记住，在管理多个实验时，受众重叠成为一个问题：确保用户不会接触到可能扭曲结果的冲突实验。

### 统计上显著的样本量和实验持续时间

在运行实验之前，使用功效分析计算最小样本量。这有助于定义实验需要运行多长时间才能得出可靠的结论。一个“功效不足”的实验可能会浪费宝贵的时间，因为样本量不足可能导致结论不明确或误导性结果。仔细考虑实验持续时间：如果你的结果似乎不明确，预先定义的停止标准可以帮助你决定何时结束实验，无论是由于达到统计显著性还是满足性能阈值。这种方法可以防止浪费精力，并确保团队不会陷入结果模糊的无尽实验中。

### 实验分离

在实践中，大多数组织不会一次只运行一个实验。相反，产品不同部分可能会有数十个正在进行的实验，这引入了新的复杂性。团队必须考虑测试交互——尤其是在实验重叠或针对相同用户时。良好的实验平台通过自动跟踪曝光、在需要时强制执行互斥性以及揭示可能的冲突来提供帮助。

### AI 驱动的解释

集成到功能管理平台中的现代人工智能助手简化了团队解读实验结果的方式。不再需要统计专业知识来分析复杂数据，AI 可以以普通语言解释结果，说明实验结果的意义。例如，当一项实验显示转化率提高了 5%，但平均订单价值略有下降时，你可以要求 AI 解释这些权衡及其商业影响。AI 可以同时分析多个指标，识别相关性，并提出可能不太明显的潜在关系。

为了做出自信的产品决策，我们需要信任实验提供的见解。通过设计包含这些关键元素的实验，我们可以确保它们的可靠性和准确性。

## 将实验与渐进式交付集成

正如我们逐步推出“订阅支付”等新功能以降低风险一样，我们可以使用功能标志以受控和安全的方式实施实验。例如，想象我们开发了一个修订的“订阅支付”工作流程。这次迭代旨在简化用户体验。我们的假设是，这个版本将导致订阅注册的增加。

为了测试这个假设，我们使用功能标志将用户分为两组：一组体验原始工作流程，而另一组则与更新后的版本互动。通过随机分配用户，我们确保了公平的比较，并收集了关于关键指标（如注册率和完成时间）的可靠数据。这种方法使我们能够在实际条件下评估新工作流程的性能，而不会将整个用户基础暴露于潜在问题。

如果指标显示更新版本在推动注册方面优于原始版本，我们可以开始逐渐将其推广到更大比例的用户。迭代过程不仅降低了风险，还确保我们的决策基于真实数据，这些数据要么证实要么反驳我们的假设。

## 建立护栏

我们讨论了在定义实验假设时确定关键指标的重要性。同样重要的是确定一个或多个护栏指标。

例如，我们与一家将贷款寻求者与贷款提供者匹配的公司合作。贷款寻求者使用注册流程提供有关他们感兴趣的贷款类型以及其他一些细节的信息。该服务能够将用户与最能满足他们需求的贷款提供者匹配。

产品团队对重新设计的注册流程将提高贷款匹配质量充满信心。他们首先小心翼翼地将这个实验推广到一小群用户中。在推广过程中，团队发现新的流程导致大量用户流失，这些用户在完成实验之前就离开了。在这种情况下，护栏指标（即流失率）帮助团队几乎在实时内检测并采取行动。

通过分析数据，产品团队可以决定采取什么行动。他们可以缩小群体规模或暂停更广泛的推广，这样他们就可以利用实验继续了解对目标指标的影响，同时限制副作用。或者，如果产品团队认为副作用对整体业务价值损害太大，他们可以完全取消实验。

与之前的例子中流失率这样的护栏指标不同，它们服务于不同的目的，但在确保实验成功方面同样重要。虽然目标指标衡量实验的主要目标——例如提高转化率、增加收入或增强用户参与度——但护栏指标作为安全检查，用于监控意外的负面后果。用于护栏的示例指标包括跳出率、页面加载时间、客户流失率、错误率和次要产品线的转化率。

护栏指标帮助你保持对实验影响的整体视角，使你能够在主要目标与产品的整体健康和可靠性之间取得平衡。通过跟踪这两者，你可以做出明智的决定，关于何时继续、暂停或调整实验。

最有效的护栏是自动化的，并且无缝集成到实验过程中。现代特征管理系统可以实时监控护栏并自动执行阈值。通过使用机器学习来识别可能逃过人类注意的微妙模式，AI 驱动的异常检测显著增强了护栏监控。这些系统建立基线指标行为，并在实验变化导致意外偏差时自动发出警报，甚至在达到预定义的阈值之前。此外，AI 可以同时关联多个指标以检测简单阈值监控可能错过的复杂交互。

自动化通过减少因人为错误而意外错过性能下降的机会来保护你的系统。将护栏作为实验过程的核心部分有助于支付平台保持敏捷性，同时保持可靠性。这种方法确保新功能可以提供价值，而不会危及用户信任。

# 没有成熟特征管理工具的生活

虽然特性管理系统提供了巨大的价值，但它们的有效性和成本效益取决于它们的实施和治理。依赖于脆弱的自建解决方案或多个分散的实施可能会对你不利，尤其是当这些基本解决方案缺乏定义现代特性管理平台所需的复杂人工智能能力时。当团队的需求是基本的时候，许多团队自然地会从构建自己的特性管理系统开始。然而，随着需求的变得更加复杂，添加更多和更多功能的努力变得越来越难以证明其合理性。这种努力的代价，以及累积的技术债务，最终会超过任何初始节省。在本节中，我们将更详细地探讨 DIY 系统的缺点。

## 低质量工具阻碍了有效的特性标志管理

没有适当的工具和治理，特性标志可能会成为负债。挑战在于基本特性标志实现与真正有效的特性标志大规模管理之间的差距。随着特性标志的采用在团队和项目中扩散，仅关注简单切换而不进行测量的第一代解决方案，以及最初为解决简单用例而构建的内部解决方案，很快就会暴露出它们的局限性。没有复杂的管理能力，团队难以维持对其不断增长的特性标志生态系统的可见性和控制。
